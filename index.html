캐시 라우팅 워크스루

과거 캐시를 전부 읽지 않는다. 라우터가 라운드마다 지금 필요한 방 4개만 골라 그 방의 원본 KV 를 손실 없이 읽고, 새로 찾은 정답이 없는 라운드가 나오면 멈추되, 질의마다 처음 한 번은 한 라운드 더 본다 — 인내의 보너스 라운드, 학습이 끝난 모델에 추론 때만 켠다. 정답이 몇 개인지 몰라도 필요한 만큼 읽는다. 파랑 삼각형 질의 하나를 추론과 학습 양쪽에서 끝까지 따라간다.

예시의 점수·방 번호는 설명용으로 지어낸 값 — 실측은 “실측” 이라고 표시 방 32개 · 프레임 128장 라운드당 4칸 · 최대 8라운드 정지: 0히트 라운드 · 보너스 1번 d_model 256 · d_key 64 · 12층 본문 예시는 N = 32 기준 — N = 64 실측은 결과

데이터셋 — 방 32개, 질의, 라벨

전체 흐름 — 그림 한 장에서 방 여섯 개를 다시 그리기까지

방 32개를 먼저 보고 캐시를 쌓는다. 사용자가 파랑 삼각형을 그리면, 라우터가 라운드마다 방 4개를 골라 읽고, 새 정답이 안 나오는 라운드에서 멈춘다 — 질의마다 처음 한 번은 한 라운드 더 본다. 찾은 방마다 그 방에 있던 자리와 크기 그대로 다시 그린다.

추론 — 학습이 끝난 모델이 한 판을 처리한다

관찰 방 32개 → 사용자가 그린 파랑 삼각형. 정답은 방 03 · 05 · 11 · 19 · 21 · 28 과 각 방의 위치·크기지만, 모델은 정답이 6개라는 걸 모른다. 이 파트의 점수는 모두 설명용으로 지어낸 값이다.

01

관찰 — 캐시를 쌓는다 (프리필)

방 03 을 지나는 동안 프레임 4장이 들어온다. 한 장은 16 × 16 격자이고 칸마다 0(빈칸) 또는 1~4(색) 값이다. 칸마다 원핫으로 펼치면 1,280 개 숫자, 선형층을 거쳐 256차원 벡터 하나가 된다.

128장(방 32 × 4장)을 순서대로 12층 트랜스포머에 통과시킨다. 인과 어텐션이라 앞 방은 볼 수 있고 뒤 방은 못 본다. 층마다 K·V 가 남는다 — 이게 LLM 의 프리필이 KV 캐시를 채우는 단계다.

캐시에 남는 것
프레임 128장 × 12층 × (K, V)   각 256차원
방 03 의 몫 = 프레임 4장 × 12층 × 2 × 256 = 24,576 개 값

압축하지 않는다. 요약하지 않는다. 안 읽는 방도 그대로 남는다.
02

방 03 의 키 — 주소 라벨을 한 번 만든다

방 03 의 마지막 층 상태 h₀ … h₃ 에 모델 전체에 하나뿐인 프로브 u 를 댄다.

점수   aᵢ = u · hᵢ
가중치 w  = softmax(a₀, a₁, a₂, a₃) = [0.03, 0.37, 0.37, 0.23]      ← 지어낸 값
접기   pooled = 0.03·h₀ + 0.37·h₁ + 0.37·h₂ + 0.23·h₃             256차원
투영   k₀₃ = normalize(W · pooled)                                64차원, 길이 1
방 32개 모두 이렇게 해서 키 32개가 준비된다. 키는 질의와 무관하게 만들어지므로 한 번 만들어 두고 모든 질의가 재사용한다.
03

질의 그림 → q₁

사용자가 그림판에 파랑 삼각형을 (11,9) 크기 0 으로 그렸다. 이 그림은 관찰 프레임과 똑같은 형식의 격자가 되고, 관찰과 같은 12층을 혼자 통과한다 — 자기 자신만 보고 캐시는 읽지 않는다. 마지막 층 상태를 W_q 로 투영하고 길이를 1로 맞춘 게 q₁ 이다.

질의 격자 → 256차원 → 12층 (질의 한 장만) → 정규화 → W_q → normalize → q₁  (64차원)
왜 12층을 통과시키나. 질의 도형은 위치·크기가 무작위다. 픽셀에 선형 투영만 걸면 “위치와 상관없이 모양을 가리는” 일을 못 한다 — 반지름 2 에서 원과 삼각형은 둘 다 13픽셀이라 픽셀 개수로도 안 갈린다. 실측: 선형 질의일 때 q 만 오라클로 바꾸자 정답을 전부 읽은 질의가 0.835 → 1.000 이 됐다 (병목이 q 였다). → 설계 결정 05

정지 규칙     새 히트 0개 라운드에서 바로 멈춘다 — 인내의 보너스 라운드는 학습에 없다

가중치        coef = 1 + gate − sg(gate)       sg = 기울기 끊기
              순전파는 1, 역전파는 gate 의 기울기  (straight-through)
조기 종료     배치 64 × 질의 8 전원이 멈추면 남은 라운드 계산을 건너뜀
일찍 멈춰서 놓친 정답은 손실로 돌아온다. hard 에서 파랑삼각 질의가 2라운드 뒤 멈춰 21 을 못 읽었다면, 21 은 다음 절의 히트 판정 BCE 에서 “히트였어야 한다” 로 채점된다 — 라우터가 21 을 앞 라운드로 끌어올리게 된다.

조기 종료는 결과를 바꾸지 않는다 (실측). 계산한 라운드가 8 → 1 · 6 · 7 로 줄어도 손실·지표·선택·판정이 같았고, 위치·크기 로짓 차이는 최대 1.9 × 10⁻⁶ (부동소수점 끝자리).
왜 학습에는 인내의 보너스 라운드가 없나. 모델은 forward 에서 정지 규칙을 보지 못하지만, 규칙은 어떤 손실이 걸리는지를 바꾼다. 추론 12절의 판을 학습 중에 만났다고 하자 — 1라운드 4칸이 25 · 15 · 32 · 07 이고, 정답 03 · 11 · 19 · 05 가 바로 아래 5~8위다.
  • 보너스 없이 학습 (채택) — 1라운드에서 멈춘다. 정답 6개가 전부 “안 읽은 방” 이라 손실 ① 에서 pos_weight 7 이 붙은 큰 벌을 받고, 그 기울기가 03 · 11 · 19 · 05 의 점수를 1라운드 컷 위로 밀어 올린다.
  • 보너스를 켜고 학습했다면 — 2라운드(보너스)에서 03 · 11 · 19 · 05 가 읽혀 칸 판정으로 “히트” 채점을 받는다. 손실 ① 의 큰 벌이 사라지고, 순위를 미는 건 손실 ④ 의 λ × 1 × BCE 뿐이다 (λ = 0.05). 모델이 “5~8위면 보너스가 주워 준다” 에 기대어 순위를 느슨하게 둘 수 있다.
목표가 “가능한 한 덜 읽기” 이므로 학습은 엄격하게(보너스 없이) 하고, 보너스는 학습이 끝난 모델에 붙이는 추론 규칙으로 쓴다. 정답 라벨을 쓰지 않으니 배포할 수 있는 정상 동작이다. 추론에만 켜도 원래 멈춘 라운드까지의 출력은 켜지 않았을 때와 칸 단위로 같다 (실측) — 보너스는 더 읽기만 한다. 순위 압력을 더 조이는 건 λ 를 올려서 한다 (다음 학습 λ = 0.1).

  • affine 계수는 끊는다. route_a · route_b 로는 기울기가 안 간다 — 벌점이 안 읽은 방 판정의 눈금을 휘지 않게. (실측: 벌점 기울기가 route_a · route_b · 히트 헤드에서 0)
  • 일찍 멈춰서 피할 수 없다. 21 · 28 을 아예 못 읽고 멈추면 이 벌점은 0 이 되지만, 대신 손실 ① 에서 pos_weight 7 이 붙은 더 큰 벌을 받는다.
  • 학습에는 보너스 라운드가 없다. 그래서 이 벌점이 받는 “늦게 찾은 정답” 은 보정 덕에 2라운드 이후에 찾은 정답뿐이고, 한 라운드가 통째로 비정답이라 멈춰 못 찾은 정답은 ① 이 크게 벌한다.
  • 보너스를 학습에 넣으면 신호가 옮겨 간다. 5~8위에 있다 못 읽고 멈출 정답은 원래 ① 의 “안 읽은 방” 항(pos_weight 7)이 크게 민다. 보너스로 읽히면 그 방은 칸 판정으로 채점되고, 1라운드 순위를 미는 건 이 벌점(λ)뿐이다 — 그래서 학습 때는 보너스를 켜지 않고, 순위 압력은 λ 를 올려 조인다 (05).
  • 왜 “라운드 수 × λ” 가 아닌가. 멈추는 건 규칙이라, 라운드 수에 벌점을 걸면 기울기가 히트 판정으로만 흘러 “히트 아니라고 해서 일찍 멈춰라” 를 배운다 = 정답을 놓친다.
  • λ 는 작게. 정답이 4개보다 많으면 1라운드 4칸에 다 못 담으니 일부는 늘 벌점을 받는다. λ 가 크면 이룰 수 없는 목표가 다른 손실을 방해한다. λ = 0 과 λ = 0.05 를 같은 설정으로 나란히 학습해 비교했다. λ = 0.05 모델에 추론 보너스를 켠 것이 N = 32 의 프론티어(전부완수 0.9990)다. λ = 0.1 학습은 보류했다 — N = 32 에서 λ 로 줄일 여지가 3.6 %p 뿐이라 규모를 올리는 쪽을 택했다 (결과 · N = 64).

01

고정 top-k 의 천장 — 필요한 방이 k 를 넘으면 정보를 잃는다

가정: 파랑 삼각형 방이 10개인 에피소드
고정 top-8 한 번   → 8칸에 10개를 못 담는다 → 최소 2개를 원리상 놓친다
라운드 + 정지      → 4칸씩 계속 읽다가 새 히트 0개에서 멈춘다 → 10개 + 확인 1라운드 + 인내의 보너스 라운드 1
실측 이력. 1라운드 k=8 에서 찾기 0.921. 2라운드 × 4칸(같은 25 %)에서는 정답 7개 질의가 전부 읽힌 비율이 0.82 에 멈췄다 — 8칸 중 오답이 1칸만 허용되기 때문. 예산을 31 %(2+8)로 늘리면 99 % 를 넘었지만, 그건 이 데이터의 정답 상한이 7이라서일 뿐 “필요한 만큼 읽기” 가 아니다. LLM 에서는 읽어야 할 그룹이 몇 개일지 보장이 없다.
02

점수 분포가 틀어지면θ 가 통째로 어긋나 완전히 망가진다순위는 유지되고, 다음 q 는 읽은 것으로 보정된다
임계값정하기 어렵다필요 없다
“전부 읽기” 방지읽은 수 벌점 필수정지를 학습하지 않아 고를 수 없음
실측 근거. 안 읽은 방을 “점수 > 0.536 이면 히트” 로 판정하던 경로가 헛것을 질의의 3.4 % 에서 냈고, 같은 모델에서 q 만 바꾸자 10 % 로 뛰었다. 절대값 기준은 점수 분포에 묶여 있다.

한때 구현했던 것: 라운드마다 헤드가 "안 읽은 방에 정답이 남았나" 를 예측, 라운드 벌점으로 학습

알아야 하는 것                 안 읽은 28 방에 정답이 더 있나  ← 읽은 것만으론 원리상 알 수 없다

두 런(λ = 0 · 0.05)이 전부완수 99 % 를 못 넘었다. 실패를 원인별로 나누고 후보를 하나씩 재 본 뒤(전부 실측, 재학습 없음) 정지 규칙에 보너스 한 라운드를 더했다. 원인 자체는 아직 고치지 않았다 — 이 결정은 “먼저 99 % 를 확보하는” 쪽이다.

추론의 여유를 어디에 줄까 — 칸을 늘리기(k+1) vs 멈출 때 한 번 더(보너스)

학습은 엄격하게, 추론은 조금 여유 있게 — 인내의 보너스 라운드를 학습에서 뺀 것도, k = 4 로 학습해 k = 5 로 추론하는 것도 같은 원리다. 차이는 여유를 쓰는 자리다.

LLM 에 대응시킨다면 — 같은 방식. 방 = 문서 청크 · 대화 턴 · 파일, 라운드 = 관련 그룹 k 개 읽기, 0히트 = “이번에 읽은 것 중 쓸모 있는 게 없음”, 보너스 = 조기 종료의 인내 1 (“없다고 결론 내리기 전에 한 번만 더 본다”). 학습은 작은 k 로 엄격하게, 추론은 같은 k + 멈출 때 한 번 더. k 는 매 단계의 지연 · 메모리와 바로 묶이지만 보너스는 질의가 끝날 때 한 번 드는 비용이다. “X 를 전부 나열” · 집계처럼 하나만 놓쳐도 틀리는 과제(PLAN §7.1)에서 가장 값지다. 미검증: LLM 은 그룹 경계가 흐리고 관련도가 연속적이라 “0히트” 판정 자체가 이 테스트베드보다 어렵다.
